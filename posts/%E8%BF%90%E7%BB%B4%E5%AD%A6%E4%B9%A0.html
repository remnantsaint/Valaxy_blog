Linux 基础 ​

进程、线程、CPU ​

操作系统创建一个进程时，为它提供执行所需的资源，包括：独立的虚拟地址空间；程序代码、堆、栈等内存区域；打开的文件、网络连接等资源；进程 ID（PID）及相关管理信息。

线程是进程内部的执行单元，一个进程可以包含多个线程，线程可以并发执行任务。

一个 CPU 核心在同一时间只能执行一个线程。

CPU在不同任务之间切换时，需要保存当前任务的执行状态，并恢复下一个任务的状态，这就是上下文切换。需要保存或恢复的状态包括寄存器、程序计数器等。用户态切换到内核态，不一定发生线程上下文切换，比如一次系统调用可能由同一个线程进入内核处理，然后直接返回用户态。

用户态：普通应用程序通常运行的状态，权限收到限制。内核态：Linux 内核执行时的特权状态，可以访问受保护的系统资源。

常见系统调用有：read()读取文件描述符的数量；write()写入文件描述符的数据；openat()打开文件；socket()创建socket；clone()创建任务，常用于进程或线程创建；execve()执行新的程序。

top命令可以查看：us（用户态CPU时间占比）；sy（内核态CPU时间占比）；id(CPU空闲时间占比)；wa（I/O wait时间占比）；si（软中断处理时间占比）；st（虚拟化环境中被宿主机占用的时间占比）

us很高，可能存在应用计算密集型任务或死循环；sy很高，可能存在大量系统调用、内核处理或网络相关开销；wa很高，可能与存储I/O等待有关，需要结合磁盘延迟和进程状态判断。

为什么单个进程的CPU使用率可能超过100%？ 因为一个逻辑CPU的计算能力按100%算，所以一个多线程进程在多个CPU上并行运行，可能达到200%甚至更高。

uptime 命令查看系统 Load Average（系统平均负载），输出后面三个数组分别对应过去1、5、15分钟平均负载。在 Linux 中，负载主要反映处于以下状态的任务数量：R（正在运行或等待CPU运行的任务）、D（处于不可终端睡眠状态的任务，常见于等待某些I/O完成。

CPU使用率主要描述CPU时间实际被如何使用，平均负载描述系统运行或等待的任务负载。

CPU使用率低，但是平均负载很高，可能是大量任务处于 D 状态，正在等待存储设备或文件系统操作完成。

ps -eo pid,stat,comm命令，可以看到进程的状态，最重要的是以下状态：R（正在CPU运行或等待调度）、S（可中断睡眠，通常在等待事件）、D（不可中断睡眠，常涉及I/O等待）、Z（子进程已退出，父进程尚未回收退出状态）、T（被暂停，例如收到停止信号）。

运维常见命令：

  • uptime 查看运行时间和负载
  • nproc 查看当前环境中可供处理的逻辑CPU数量
  • top 查看CPU和进程
  • ps -eo pid,ppid,stat,pcpu,pmem,etime,time,comm --sort=-pcpu | head 查看CPU占用最高的进程
  • top -H -p (pid) 查看某进程的各个线程，不加 -H 就是看整体线程

线上服务器 CPU 使用率突然到100%，网站访问很慢，怎么排查？ 先用uptime、top确认负载与CPU时间分布，然后用ps、top -H定位进程与线程，之后根据结果判断。

内存管理、Swap与OOM ​

物理内存：服务器实际安装的RAM；虚拟内存：操作系统提供给进程的一种内存地址空间抽象。

虚拟内存的好处：内存隔离（不同进程默认无法直接访问对方的私有内存）、内存保护（操作系统可以限制某块内存是否允许读取、写入、执行）、按需分配（进程申请很大的虚拟地址空间，不意味着立即占用同样大的物理内存）

虚拟内存是一整套内存管理机制，Swap 只是其中可以用于存放部分内存页的后备存储机制。

free -h命令，查看系统内存使用情况，-h 表示使用人类易读的单位

top命令看到的 VIRT、RES(RSS)、PSS。其中 VIRT 表示进程虚拟内存大小，这个大小可以预留；RSS 表示实际驻留的物理内存，包含共享内存页；PSS 表示按比例分摊共享内存，用于改善RSS 对共享内存的重复计数问题。

用ps -eo pid,comm,rss,%mem --sort=-rss | head命令看占用物理内存较高的进程（改sort）。

Swap 是 Linux 可以使用的交换空间，通常位于磁盘上的交换分区或交换文件。当系统存在内存压力时，内核可能将部分匿名内存换出到 Swap，以释放物理内存。

vmstat 1命令可以查看 swap 相关的信息，持续换页情况。swap 使用率很高，不能说明内存不足，因为 swap 中可能保留一些很久没有访问的页面，所以仅看已用容量无法判断当前压力，得看是否持续有大量换入换出同时出现业务延迟增加。

OOM 内存不足，当linux 无法满足必要的内存分配需求，并且经过内存回收等处理后仍无法解决问题时，可能触发 OOM Killer。sudo journalctl -k --since "30 minutes ago" | grep -Ei 'out of memory|oom|killed process'命令，journalctl 查看 systemd journal 日志、-k 只查看内核日志、–since 限定开始时间、grep -E 使用扩展正则表达式匹配、grep -i 忽略大小写。

一个服务的内存占用持续增长，一般是什么原因？ 内存泄漏、缓存增长、并发增长。

磁盘、文件系统与 I/O 性能排查 ​

磁盘是存储数据的设备，HDD（机械硬盘）、SSD（固态硬盘）、云盘。在 linux 中设备名称一般是 /dev/xxxx，比如 /dev/sda1 表示一块SCSI类块设备的第一个分区。

文件系统用于管理文件内容、目录结构、权限、元数据和空间分配等，常见的有 ext4、XFS、Btrfs、tmpfs。

Linux 使用以 / 为根的统一目录树，文件系统可以挂载到其中某个目录，例如把 /dev/sdb1 挂载到 /data 后，访问 /data 就是在访问这个文件系统。

用lsblk -f或 df -hT查看文件系统。lsblk 列出块设备，-f 显示文件系统类型、UUID、挂载点等信息。df -hT 中，-h 是便于阅读的单位显示容量，-T 显示文件系统类型。

df -h查看文件系统空间，du -xhd1 /var查看var目录下的占用。df 判断文件系统是否块满，du 定位哪些目录、文件占空间。 df 可能包括已删除但仍被进程打开的文件，所以可能比du 显示的占用空间大。

inode（索引节点）用于保存文件的元数据信息，例如文件所有者所属组、文件权限、文件大小、创建、修改、访问等时间信息、文件数据块的位置等相关信息。对于 ext4 等文件系统，inode 数量可能在创建文件系统时就已经确定，所以如果磁盘容量还有剩余，但是 inode 耗尽，可能无法创建新文件。

用df -i 查看inode的inode总数和已使用和剩余还有使用率。创建大量小文件可能导致 inode 耗尽，用find /var/log -xdev -type f | wc -l 命令查看某目录下文件系统对象的数量。

文件删除，为什么磁盘空间没释放？ 删除后，ls 看不到，但是执行 df -h 还是能看到。这是因为删除一个文件名意味着移除目录中对应的链接，如果某个进程仍然打开着这个文件，内核还保留着对应的文件对象引用，即使目录中已经没有这个文件名，文件内容占用的磁盘空间仍可能继续保留。

sudo lsof +L1可以查看链接数小于 1 的已打开文件，也就是常见的已删除但仍被进程持有的文件。

磁盘 I/O 就是读取和写入数据，有四个核心指标：吞吐量（单位时间传输的数据量）、IOPS（每秒完成的I/O操作数量）、延迟（一次 I/O 请求的响应时间）、队列深度（等待或正在处理的I/O请求数量）

iostat -xz 1可以监控磁盘 I/O 信息，iostat 查看 CPU 和块设备 I/O 统计、-x 显示扩展 I/O 指标、-z 不显示采样期间没有活动的设备、1 表示每隔一秒输出一次。

pidstat -d 1 命令查看进程的磁盘 I/O 信息，定位哪个进程正在大量磁盘 I/O。

如果磁盘空间不足，服务写入失败，怎么排查？ 先确认故障文件所在文件系统，用 df -h 和 df - i命令，然后定位空间被谁占用，用 du -xhd1 命令。

用户权限、systemd 服务管理与日志排查 ​

Linux 是一个多用户操作系统，通过用户和用户组控制每个人能够访问、修改和执行哪些资源。UID：用户 ID，用于标识用户。GID：组ID ，用于标识用户组。

id命令可以看当前用户的信息。whoami查看当前用户名。groups查看用户所属组。useradd创建用户。passwd设置或修改密码。usermod修改用户属性。userdel删除用户。groupadd创建用户组。

比如创建一个名为 app 的用户：sudo useradd -m app，其中，-m 同时创建用户目录；设置密码：sudo passwd app；添加到 dev 用户组sudo usermod -aG dev app其中 -a 是追加，-G 指定附加组；id app查看用户信息。

用户信息存在哪里？ /etc/passwd用户账号基本信息、 /etc/shadow用户密码哈希及密码策略信息、 /etc/group用户组信息。

Linux 文件权限，r表示读取，值是 4；w 表示写入，值是 2；x 表示执行，值是 1。比如rwx r-x r--前三位是所有者权限、中三位是所属组权限、后三位是其他用户权限，- 表示不能做。

chmod 修改文件权限，比如 chmod 755 app.sh，其中755就是上面九位合起来的三位的数字表示，7表示读写执行，5少个2表示读执行。也可以用符号表示法，chmod u+x app.sh，其中 u 表示所有者，g 表示所属组，o 表示其他用户，a 表示所有用户，+ 表示增加权限，- 表示删除权限，= 表示设置权限。

chown修改文件所有者，比如把某个文件改成让别的用户管理：sudo chown app app.log。用sudo chown app:dev app.log同时改所有者和所属组。

systemd 用于 Linux 服务管理，服务可能需要在系统启动时执行、自动重启、管理依赖、记录日志等等。systemd 是现代 Linux 发行版中常见的系统和服务管理器，通常作为 PID 1 的系统初始化进程运行，负责启动和管理系统服务。

systemctl 是管理 systemd 的主要命令行工具，日常运维最常用命令如下：

shell
systemctl status nginx 查看服务状态
systemctl start nginx	启动服务
systemctl stop nginx	停止服务
systemctl restart nginx	重启服务
systemctl reload nginx	重新加载服务配置
systemctl enable nginx	设置开机自启
systemctl disable nginx	取消开机自启
systemctl enable --now nginx 立即启动并设置开机自启

其中 reload 和 restart 区别是：restart 停止服务然后重启，reload 是让服务重新加载配置，但是有的不支持。

systemd 用 unit 文件描述服务、挂载点、定时任务等资源，如果想让自己的服务作为系统服务运行，需要编写一个 systemd unit 文件。具体先不展开。

journalctl 用于 Linux 日志排查，是 systemd 提供的日志查询工具，用来读取 systemd journal 中保存的日志，可以查看：系统启动日志、内核日志、服务日志、服务启动失败信息、某个时间段的日志。

journalctl -u nginx -n 100 --no-pager查看某个服务的日志，-u 是指定 unit，-n 是指定看最近多少行，–no-pager 是不进入交互式分页界面。journalctl -u nginx -f实时查看日志。–since "1 hour ago" 查看最近一小时、–since today 查看今天日志。

journalctl -p err表示查看错误级别日志，其中 -p 表示指定日志优先级，有很多级别，比如 err 就是错误级别的日志。 journalctl -k -b查看本次启动的内核日志。

为什么服务手动启动正常，systemctl 启动却失败？ 两种方式最大区别是可能处于不同的运行环境，比如用户、工作目录、环境变量、执行路径、权限等等。排查方法是先看服务状态sudo systemctl status myapp，然后看具体日志sudo journalctl -u myapp -n 100 --no-paper，然后检查服务配置和文件权限执行路径，检查端口是否冲突sudo ss -lntp。简单来说就是对比各种信息是否相同，比如用户、工作目录、执行路径、环境变量、文件权限、配置文件、端口等等。

Linux 故障排查五步法

  1. 确认现象：业务出现了什么问题？从什么时候开始？影响范围有多大？
  2. 检查资源：CPU、内存、磁盘、网络是否存在异常？
  3. 定位对象：是哪个进程、线程、服务或依赖组件出现问题？
  4. 分析根因并处理：根据日志、指标和配置找到真正原因，采取有针对性的措施。
  5. 验证与复盘：确认服务恢复、业务正常，并分析如何避免再次发生。

计算机网络与 Nginx ​

TCP/IP 网络基础 ​

TCP/IP 是一组网络通信协议集合，是互联网通信的基础。当在浏览器访问网站到看到内容，涉及多个协议：HTTP定义浏览器和服务器之间如何交换Web数据、TCP提供可靠有序的字节流传输、IP负责数据包寻址和路由转发、Ethernet负责局域网链路上的数据传输

TCP/IP 四层模型：

  • 应用层：处理应用程序间的通信，HTTP、HTTPS、DNS、SSH

  • 传输层：负责端到端的数据传输，TCP、UDP

  • 网络层：负责IP寻址和路由，IP、ICMP

  • 网络接口层：负责链路上的数据传输，Ethernet、WIFI

    OSI 七层模型：应用层、表示层、会话层、传输层、网络层、数据链路层、物理层

    发送一条HTTP请求，数据会逐层封装：应用层，HTTP请求数据；传输层，TCP头部+HTTP数据；网络层，IP头部+TCP数据；网络接口层，链路层头部+IP数据

    TCP是传输控制协议，面向连接、可靠的传输层协议。特点：通信前建立连接、提供可靠的数据传输机制、保证接收端按照争取恶的顺序交付数据、提供流量控制和拥塞控制、通过确认和重传等机制处理丢包。字节流

    UDP是用户数据报协议，无连接的传输层协议。特点：不需要事先建立连接、不保证数据一定到达、不保证数据按发送顺序到达、没有TCP那样的内置可靠传输和流量控制还有拥塞控制机制、协议头部开销小。可用于DNS查询、实时语音等等。数据报

    使用TCP因为是字节流的，可能发生粘包，处理方法就是区分消息边界，自己设定消息长度字段、分隔符等协议。UDP是数据报，独立的，所以接收端通常按照数据报边界读取。

    三次握手建立连接，具体看面经学习文章的计算机网络部分。

    为什么不是两次握手？假设只有两次握手，没有最后一次客户端发送ACK，那么服务器无法确认自己的 SYN 是否成功到达客户端，也无法确认客户端已经收到并确认服务器的初始序列号，第三次握手是为了让服务器确认客户端确实受到了服务器的响应，也能降低历史延迟SYN报文早曾错误连接建立的风险。

    SYN Flood 攻击是什么？ 是一种 TCP 拒绝服务攻击，攻击者大量发送 SYN 请求，但不完成后续握手，导致服务器需要处理大量半连接请求，消耗连接队列资源。

    TCP 四次挥手关闭连接。为什么需要四次挥手？因为 TCP 是全双工通信，客户端和服务器两个方向的数据传输可以独立进行，因为两个方向需要分别关闭。客户端先发个fin，服务端发个ack确认收到，等服务端准备好关闭后发送fin，客户端收到后发送ack。

    为什么不是三次挥手？因为 TCP 两个方向的数据传输可以独立关闭，服务端收到客户端 FIN 时，可能还有数据没有发送完。

    TCP常见连接状态： | 状态 | 含义 | | ---- | ---- | | LISTEN | 服务端正在监听端口 | | SYN_SENT | 客户端已发送 SYN，等待响应 | | SYN_RECV | 服务端收到 SYN，等待客户端确认 | | ESTABLISHED | 连接已建立 | | FIN_WAIT_1 | 主动关闭方已发送 FIN，等待确认 | | FIN_WAIT_2 | 已收到对 FIN 的确认，等待对方 FIN | | CLOSE_WAIT | 已收到对方 FIN，等待本地应用关闭 | | LAST_ACK | 已发送 FIN，等待最后 ACK | | TIME_WAIT | 主动关闭方等待一段时间后完成关闭 | | CLOSED | 连接已关闭 |

    TIME_WAIT 通常出现在主动关闭 TCP 连接的一方，第一确保最后的 ACK 能够被对方收到，第二避免旧连接的延迟报文影响后续新连接。

    CLOSE_WAIT 表示远端已经发送 FIN，通知本端不再发送数据，但本端应用程序还没有关闭对应的 Socket。

    TIME_WAIT 通常出现在主动关闭连接的一方，主要为了确保最后的 ACK 能够被对方收到，并避免旧连接报文影响新连接。CLOSE_WAIT 表示本端已经收到对方的 FIN，但本地应用还没有关闭 Socket。如果出现大量 CLOSE_WAIT，应该重点检查应用程序是否正确释放连接。

    ss -ant命令查看 TCP 状态。ss -ant state established查看已建立的连接。ss -ant state time-wait查看TIME_WAIT。ss -s统计TCP连接。sudo s --lntp查看监听端口以及对应进程。

    TCP流量控制解决发送方发送数据太快，接收方处理不过来的问题，用滑动窗口机制处理。拥塞控制解决网络本身的传输能力有限，发送过快可能导致网络拥塞，用慢启动、拥塞避免、快重传、快恢复机制处理。

    TCP为什么丢包？可能发生网络链路拥塞、路由器缓冲区溢出、网络设备故障、无线网络信号不稳定、防火墙或网络策略丢弃数据包。

    TCP如何发现丢包？超时重传（RTO）：发送方发送数据后，如果在一定时间内没有收到相应确认，就可能触发重传。快速重传：如果发送方收到多个重复ACK，可能推断某个数据段丢失，并提前重传，而不必等待超时。

    ping -c 4 8.8.8.8ping命令检查网络连通性，-c 表示发送几次请求。

    ss查看TCP连接，上面说过，常用命令是ss -lntp、ss -ant、ss -s，可以查看端口是否监听。

    traceroute 8.8.8.8 擦看网络路径，可以帮助查看数据包经过的路由节点。

    tcpdump 抓包工具，可以捕获网络接口上的数据包，帮助分析 TCP 握手、连接失败、重传和数据传输等问题。比如sudo tcpdump -i any -nn 'tcp port 80'其中 -i any 监听所有适用网络接口，-nn 不解析主机名和端口服务名，tcp port 80 只抓取 TCP 80 端口相关流量。

    如果客户端无法连接服务器 8080 端口，第一步确认服务器端口是否监听sudo ss -lntp | grep ':8080'，然后检查服务是否启动systemctl status myapp，之后用 ping 检查网络连通性，用nc -vz 192.168.1.20 8080 检查 TCP 端口连接，还可以抓包分析sudo tcpdump -i any -nn 'tcp port 8080'，检查防火墙firewall-cmd 或者 ufw。

DNS、HTTP、HTTPS ​

什么是DNS？ DNS是域名系统，将域名解析为 IP 地址。解析过程：浏览器发起域名查询->看有没有缓存->递归DNS解析器->根DNS服务器->.com顶级域名DNS服务器->权威DNS服务器->解析结果返回客户端。

TTL 是用于控制 DNS 记录可被缓存的时间。DNS记录类型：A（域名指向IPv4地址）；AAAA（IPv6）；CNAME（域名别名）、MX（指定邮件服务器）、TXT存储文本信息、NS（指定权威DNS服务器。

HTTP是超文本传输协议，使用典型的请求-相应模式。HTTP/1.1 和 HTTP/1.2 的常见场景中，HTTP通过TCP传输，而 HTTP/3 使用基于 UDP 的QUIC。

幂等性指的是：对服务器执行一次和执行多次相同请求，预期产生的目标效果相同。

HTTP是无状态协议什么意思？协议本身不会自动记住两次请求属于同一个登录用户，网站用cookie、session、token来保持登录。

HTTP状态码分为五大类：1xx 信息性相应；2xx 请求成功；3xx 重定向；4xx 客户端请求相关错误；5xx 服务器处理相关错误。常见状态码如下：

状态码名称常见含义
200OK请求成功
201Created成功创建资源
204No Content请求成功，但没有响应体
301Moved Permanently永久重定向

304Not Modified资源未修改，可使用已有缓存

HTTPs和HTTP区别：HTTP本身不提供传输加密，HTTPS作用就是为HTTP通信提供TLS安全保护，端口是 443。

TLS握手过程，记录在面试学习里面，以TLS 1.3为例简单流程：客户端发送ClientHello（支持的协议、算法和密钥协商参数）；服务端发送ServerHello（选择参数，随后发送证书和握手验证信息）；客户端验证与Finished（验证服务器身份，确认握手密钥）。

TLS最重要的是理解三个目的：1.协商参数，双方确定使用的TLS版本和密码算法。2. 身份认证：客户端验证自己连接的是正确服务器。3. 建立密钥：双方安全协商出用于后续通信的密钥。

HTTPs证书通常使用 X.509 证书格式，一般包含：证书对应的域名等身份信息、服务器公钥、证书有效期、颁发者信息、数字签名等。

HTTP/1.1、HTTP/1.2、HTTP/1.3有什么区别？

特性HTTP/1.1HTTP/2HTTP/3
常见底层传输TCPTCPQUIC（基于 UDP）
多路复用有限支持支持
头部压缩无专门的标准头部压缩机制HPACKQPACK
主要特点广泛兼容一个连接上复用多个流改善 TCP 层队头阻塞等问题

为什么HTTP/2 比 HTTP/1.1 更高效？HTTP/1.1 在一个连接上的请求与相应处理存在一些限制，浏览器通常需要建立多个 TCP 连接来提高并发效率。HTTP/2 基于 TCP，使用多路复用技术，可以在一个 TCP 连接中并发处理多个请求和相应流，但是用的 TCP 让然发生丢包影响其他流。HTTP/3 不基于 TCP，可以缓解这个问题。

curl命令，用于通过 URL 与服务器通信的命令行工具。

网站打不开，怎么判断问题在哪里？

  1. DNS：域名能否正确解析？用dig、nslookup
  2. TCP：服务器端口能否连接？用nc、ss、tcpdump
  3. TLS：HTTPS握手是否正常？用curl -v、openssl s_client
  4. HTTP：服务器返回什么状态码？用curl -l、curl -v
  5. 业务：检查 Nginx、后端、数据库

在浏览器输入一个 URL，会发生什么？首先，浏览器会通过 DNS 查询域名对应的 IP 地址。然后，根据使用的 HTTP 版本建立相应传输连接，例如 HTTP/1.1 和 HTTP/2 通常建立 TCP 连接。如果是 HTTPS，还需要完成 TLS 握手和服务器证书验证。之后浏览器发送 HTTP 请求，服务器处理并返回 HTTP 响应，浏览器再解析 HTML、CSS 和 JavaScript 等资源，最终渲染页面。

DNS解析的基本过程？客户端通常先检查可用的本地解析信息和缓存。如果没有结果，就请求递归 DNS 解析器。递归解析器在没有缓存时，会根据根服务器、顶级域名服务器、权威 DNS 服务器的指引逐级查询，获取目标记录，再返回给客户端。

HTTP和 HTTPs 区别？HTTP 是应用层的请求响应协议，本身不提供加密。HTTPS 在 HTTP 通信中使用 TLS，提供传输加密、完整性保护及服务器身份认证，能够降低通信被窃听或篡改的风险。

HTTPs为什么需要数字证书？数字证书主要用于验证服务器身份，并将服务器身份与公钥关联起来。客户端通过验证证书的域名、有效期和信任链等信息，判断连接的服务器是否可信，从而降低中间人攻击风险。

Nginx 与网络故障排查 ​

Nginx 是一个常见的 Web 基础设施软件，主要用途包括：1. Web 服务器：直接处理 HTTP 请求，返回 HTML、图片、CSS、JS 等静态资源。2. 反向代理：接收客户端请求，再转发给后端应用程序。3. 负载均衡：将请求分配给多个后端服务器。4.TLS中止：处理 HTTPS 加密连接，再通过配置向后端发送请求。

为什么不直接让 python 服务对外提供服务？因为生产环境通常需要一个专门的入口层，nginx 可以帮助完成：统一处理外部请求、HTTPS 证书管理与 TLS 终止、静态资源处理、请求转发、多个后端服务之间的流量分配、访问日志和错误日志管理。

正向代理是代理客户端访问外部服务器，比如自己电脑使用代理服务器访问目标网站。反向代理是代理服务器接收客户端请求，再转发到后端服务器。

nginx 采用 Master-Worker 架构，Master主进程：读取Nginx配置文件、创建和管理 woker 进程、接收管理信号、负责配置重新加载等管理工作。Woker 工作进程：接收客户端连接、处理 HTTP 请求、向后端转发请求、返回响应数据。

为什么Nginx 性能比较高？nginx 采用事件驱动、异步非阻塞 I/O 模型。利用事件循环处理大量连接，不需要为每个连接创建一个独立线程。

nginx 配置文件一般放在 /etc/nginx/nginx.conf。

反向代理配置 proxy_pass。一个简单的反向代理配置，假设 nginx 监听 80 端口，python 后端监听 8080 端口，用户访问 /api/，那么配置如下：

shell
server {
    listen 80;
    
    server_name example.com;
    8.
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
    }
}

其中proxy_pass http://127.0.0.1:8080;表示把匹配到的请求转发给 127.0.0.1：808

注意8080后不能有 / ，没 / 情况下是转发到/api/users，若有 / ，则转发到 /users，这是因为当 proxy_pass 带有 url 部分时，nginx 会将匹配到的 location 前缀替换为该 url。

负载均衡是增加多台后端，nginx 根据负载均衡策略，将请求分配给不同的后端服务器。三种常见的负载均衡策略：轮询（默认策略，请求依次分配给后端服务器，适合性能接近请求耗时均匀的场景）；最少连接（优先选择当前活动连接数较少的服务器，适合不同请求处理事件差异较大的场景）；IP Hash（根据客户端 IP 计算哈希，尽量让同一客户端的请求落到统一后端服务器，适合需要一定会话粘性的场景）

nginx如何实现负载均衡？通过 upstream 定义后端服务器组，再通过 proxy_pass 将请求转发到服务器组。常见策略有默认轮询、least_conn 最少连接、ip_hash，以及权重配置。

ngxin如何处理HTTPS？在 server 中监听 443 ssl，配置服务器证书和私钥。客户端与 Nginx 完成 TLS 握手后，Nginx 解密请求，再根据配置转发给后端服务。

502 表示网关从上游获取到了无效响应，或者与上游通信时发生了相关错误；504 表示网关等待上游响应超时。502 应重点检查后端服务、端口和上游响应，504 应重点检查后端处理时间、数据库、网络以及代理超时配置。
